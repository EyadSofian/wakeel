# 00 — Blocking questions for Eyad

Only questions whose answer changes the design. Each has the assumption the documents currently make, so work can proceed until you answer. Ordered by how early the answer is needed.

| # | Question | Current assumption | What changes if the answer differs | Needed by |
|---|---|---|---|---|
| 1 | **Is the product name "Wakeel"?** It is baked into things that become public contracts: the webhook headers (`X-Wakeel-Signature`), key prefixes (`wk_live_`, `wk_bridge_`), the CLI name and the package scope. | Code name `wakeel`; brand string `{{PLATFORM_NAME}}` read from one file. | Headers and key prefixes must be final before the first external bridge is written (Phase 4–5). Renaming later breaks every integration. | Phase 4 |
| 2 | **Where will it run?** Coolify on your own VPS, a managed Kubernetes, or a cloud PaaS? Can that host run containers under gVisor (`runsc`)? | Docker hosts you control, where gVisor can be installed. | If gVisor is not available, ADR-003 loses its container layer and we either accept that in writing, pick a different host, or move the sandbox to a microVM service. | Phase 3 |
| 3 | **May conversation content be sent to US-hosted model APIs** (Anthropic, OpenAI, Google) for all tenants, including Engosoft? Or do some tenants need in-region or self-hosted models? | Hosted APIs are allowed; self-hosted is supported through the OpenAI-compatible adapter but not provisioned. | A self-hosted requirement adds GPU serving (vLLM, TEI) to the deployment, changes the default embedding and reranker, and makes the Autonomous Node's adherence on open models a launch risk rather than a later one. | Phase 6 |
| 4 | **First region and residency promise.** Egypt, KSA, UAE or EU? Do you intend to promise customers that data stays in-country? | One region, no residency promise at launch; dedicated instances later. | An in-country promise constrains the managed Postgres, object store and model providers we can use, and pulls "dedicated instance" work forward. | Phase 15 (decide by Phase 6) |
| 5 | **Pricing model.** Per-workspace platform fee with a conversation allowance and hard caps (the thesis), or something else (per bot, per seat, pure usage)? Bring-your-own model key by default, or platform keys with a margin? | Tiered platform fee + allowance; overage off by default; BYOK default for agencies. | Changes the usage kinds we meter, what a "quota" is, and whether platform model keys and spend caps are MVP. | Phase 11 |
| 6 | **Payment provider.** Stripe is not available to Egyptian entities. Paymob, Tap, Paddle, or invoicing by hand at first? | No provider in the MVP: metering produces roll-ups and a `BillingAdapter` interface; invoices are manual. | A provider with subscriptions changes plan and entitlement modelling; one without means we own dunning and plan state. | Phase 11 |
| 7 | **Studio interface language.** English-only chrome for the MVP (bot content fully Arabic and RTL), or does the Studio itself need an Arabic, right-to-left interface at launch? | English, left-to-right chrome; all content surfaces RTL-correct. | A fully RTL Studio roughly doubles layout QA, needs a mirrored canvas policy, and a translation workflow. It is far cheaper to decide now than to retrofit. | Phase 2 |
| 8 | **Voice notes and audio.** In MENA a large share of WhatsApp messages are voice. The brief's message list has no audio. Must the bot accept audio (speech-to-text) in the MVP? | No audio type. Bridges transcribe before sending, or send a `file`. | Adds an `audio` message type to the contract, an STT provider to the model layer, and Arabic dialect STT quality as a risk. Contract changes are cheapest before Phase 4. | Phase 4 |
| 9 | **Bot-initiated messages.** Do bots need to start a turn on their own: scheduled reminders, follow-ups after N hours, campaigns? | Only reactive turns plus the inactivity trigger and custom events pushed by a bridge. An external scheduler (n8n) can send an event. | A built-in scheduler adds a schedule trigger, a durable timer service, per-conversation reminder storage and anti-spam limits. | Phase 4–5 |
| 10 | **Migrating existing Botpress bots** (Majed, Fahad, HR-in-a-Box). Is rebuilding them by hand acceptable, or is an importer for Botpress exports a requirement? | Manual rebuild; Phase 15 pilots one bot. An `axios`-shaped helper eases code reuse. | An importer means reverse-engineering a closed export format and mapping LLMz prompts and built-in tools; several weeks of work with legal care. | Phase 7 |
| 11 | **Stored content and privacy.** Traces keep full prompts, generated code, tool inputs and outputs for 30 days; conversations for 90. Is that acceptable for Engosoft and the customers you have in mind, or do some need shorter retention, PII masking before storage, or "no content stored" mode? | Store everything, redact secrets only, retention configurable per plan. | PII masking before storage adds a detection step (with Arabic name, phone and national-ID patterns) on the write path; a "no content" mode changes what the trace viewer and evals can do. | Phase 10 |
| 12 | **Selling self-hosted or dedicated deployments in year one?** | No. Multi-tenant SaaS first; the stack stays deployable so a dedicated instance is an ops task later. | If yes: licensing and packaging of the product itself, an install path without our CI, offline model options, and upgrade tooling become near-term work. | Phase 15 (decide by Phase 7) |
| 13 | **Who reviews 🔒 tasks, and is there budget for an external penetration test before the first paying tenant?** | You review; an external test is planned in Phase 15. | Without an external test, ADR-003's "defence in depth" has not been challenged by anyone but its authors; I would then narrow what tenant code may do at launch (for example, disable `fetch` from model-generated code). | Phase 3 |

## Things I decided without asking (reversible; tell me if you disagree)

- Own autonomy engine instead of forking LLMz (ADR-002).
- QuickJS-WASM in a separate service, not isolated-vm (ADR-003).
- Sync wait and SSE in addition to webhooks (ADR-005).
- Knowledge bases and tables belong to a bot, not to the workspace.
- IBM Plex as the single type family; one indigo accent.
- UI vocabulary keeps Botpress-familiar terms: workflow, node, card, Standard and Autonomous node.
- `CLAUDE.md` sits at the repo root (where the executor loads it) rather than under `/docs`.
