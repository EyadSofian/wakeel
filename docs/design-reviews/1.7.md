# Design review — 1.7 Studio: sign in, workspace home, settings (General, Members, API keys)

Screens: sign-in (default, focus, error) · home (default, focus, loading, error, rtl) · settings-general (default, focus, loading, error, rtl) · settings-members (default, focus, empty, loading, error, rtl) · settings-api-keys (default, focus, empty, loading, error, rtl) · light + dark · 1440, 1280

Method: `pnpm studio:shots` with the mock API layer (`apps/studio/tests/mock-api.ts`), 126 PNGs. I looked at them as contact sheets per screen, then at full-size crops of the focus, error and RTL shots. Dialogs (invite, new key, copy key, revoke) were checked live in the browser pane against the real api while running the flow by hand. They are not in the shot states yet.

| # | Check | Result | Evidence |
|---|---|---|---|
| 1 | Accent use | fail | Inputs turned their border `--accent-border` on hover (seen on the password field in sign-in error-dark-1440), which is decoration, not selection or focus. Elsewhere the accent is only on the one primary button per view, the active tab underline, the active rail item and links. |

| 8 | Radius hierarchy | pass | Inputs, selects and buttons 5 px; badge 3 px; dialogs 12 px (checked live). |

| 17 | Empty, loading, error, long content designed | fail | Every **error** shot (home, general, members, api keys) showed the loading skeleton. React Query retries a 500 twice with backoff, and the shot was taken before the error banner appeared, so the error state was never actually reviewed. |
| 18 | Focus ring visible | pass | sign-in focus-light-1440: 2 px accent outline with offset on Email. The other screens show it on the first rail item. |
| 19 | What would look unconsidered beside Linear | fail | The Revoked badge that breaks the row height, and the doubled "New API key" in the empty state. |

Fixes made:
- 1: removed `hover:border-accent-border` from Input and Select.
- 7: Badge is 20 px (`h-7`); table cells are `whitespace-nowrap` (32 px single-line rows, §4 DataTable).
- 10: page headings, tabs, forms and banners are inset 12 px (`px-5`, the panel padding of §2.3), matching the cells.
- 13: the empty state has no action; the top bar keeps the one primary action.
- 14: skeleton bars are `w-full max-w-node`, so they fill their cell and never widen the table.
- 15: the select stays LTR as chrome; each option has `dir="auto"`.
- 17: the shot for an error state waits for the alert (up to 15 s), so the banner itself is what gets reviewed.
