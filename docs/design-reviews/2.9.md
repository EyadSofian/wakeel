Also seen: the current-line tint stayed on line 1 after the editor lost focus, which read as focus that was not there (code-drawer, every size).

Fixes made:
- `bracketPairColorization` is off, and the theme maps every `editorBracketHighlight.foreground*` colour to the secondary grey in case Monaco draws pairs anyway. Matching brackets are shown by the muted box only.
- Code text uses Plex Mono, then Plex Sans Arabic for Arabic letters, then the generic monospace fonts (`code-font.ts`, built from `--font-mono` and `--font-sans` at run time). That follows §2.2 ("Plex Sans Arabic for Arabic content"). ADR-021 (proposed) puts it in `--font-mono` itself, so `font-mono` everywhere gets it.
- The editor has a placeholder: "Type workflow. to see its variables." The first wording was cut at 1280 ("…to see w…"), so it was shortened.
- `renderLineHighlightOnlyWhenFocus` is on.
- The inspector preview renders one block per line, each cut with an ellipsis at its end, plus "… 3 more lines".

## Behaviour found while testing (fixed, not visual)

- With Chromium's EditContext (Monaco's new input path), spaces typed in the e2e run never reached the text: `const to = workflow.email` was saved as `constto=workflow.email`. The editor uses the hidden textarea (`editContext: false`), which is also the path IME input for Arabic has been proven on.
- Monaco takes `Esc` itself, so the drawer's own `Esc` handler never fired while the editor had focus. `Esc` is now an editor command that closes the drawer only when no suggestion list, hint, find box or snippet is open, so the first `Esc` still closes suggestions.
- `⌘Enter` would insert a line. It is bound to the run action, which says "Running code arrives with the emulator. Your code is saved." until 4.6.
- Monaco reads the platform from the user agent. Playwright's Desktop Chrome preset reports Windows, so in the e2e `⌘` is Ctrl; real Mac users get `⌘`.
