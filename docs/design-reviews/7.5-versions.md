# Design review — 7.5 Publish, versions, compare, secrets and settings

Screens: versions (default, focus, empty, loading, error, rtl, rollback, restore) · version-compare (default, loading, error, rtl) · variables (secrets, secrets-rtl, secrets-empty, and every existing state, which gained the tab bar) · canvas (publish, publish-blocked, and every existing state, whose top bar's Publish is now enabled) · light + dark · 1440, 1280.

Motion: no new values. Dialogs use the shared Dialog (spring.gentle enter); pages use `wk-enter`.

Also verified on the dev stack (e2e `versions.e2e.ts`): publish blocked by the seeded empty instructions, publish, change, the change summary, compare, roll back; a secret set for Production and never shown again.

Fixes made:
- 7: the indent moved to an inner margin, so every row keeps the cell padding.
- 10, 19: the live row reserves Roll back's width with an invisible, unfocusable copy, so the buttons line up.
- 14: heading rows leave both value cells empty; only fields and transitions show values.
- 15: the description is a `bdi` inside a block, as the Connections screen does, so it stays under its key.
- 17: the Variables fixture declares SHOP_URL and SHOP_TOKEN, as a real bot with those values would.
- Also: a selector in the declare dialog returned a new array on every store read, which crashed the tab on the real stack. Found by the e2e test and fixed before this review.
