# Design review — 6.8 Autonomous node inspector

Screens: canvas (agent, agent-rtl, agent-tool, agent-exit; selection re-shot because the Autonomous node's inspector gained sections) · light + dark · 1440, 1280.

Motion: no new moments. The tool and exit sub-views use the inspector's existing content swap; no animation values were written in components.

Not in this review: the code editor drawer (§5.2 "code tools open the code editor as a bottom drawer") is not built; code is edited in a monospace textarea in the sub-view. The shots show the panel's first screen only: the Exits list and the Advanced section are below the fold in every shot and are not judged here. The e2e test builds the §5.2 node through them; they still need a scrolled shot.

## Pass 1

| # | Check | Result | Evidence |
|---|---|---|---|
| 1 | Accent use | pass | Accent only on the selected node's border, the active Configure tab, the active rail item and Publish |
| 2 | Gradients, glows, decoration | pass | None; tool rows are hairline pills like card rows |
| 3 | Status colours | fail | agent-tool: a brand-new tool opens with its Input field in error red, because the default schema used `additionalProperties`, which the validator does not support |
| 4 | Dark hierarchy | pass | agent-dark: inspector on surface, section hairlines and field borders keep the same steps as light |
| 5 | Weights, sizes, caps | pass | Section titles semibold small, field labels medium small, names mono `text-code-small` |
| 6 | Sentence case | pass | "Function name", "When to use it", "Changes things outside the conversation", "Delete tool", "Give access to" |
| 7 | Truncation and overlap | pass | `conversation.orderNumber` fits beside the Write select and the remove button at 1280 |
| 8 | Radii | pass | Fields 8, rows 8 as card rows |
| 9 | Shadows | pass | None added |
| 10 | Spacing | pass | Fields 24 apart in sub-views, as in card forms |
| 11 | Identical card grids | pass | Tools, variables and exits are lists |
| 12 | One icon set | pass | Lucide at 1.75 stroke: Braces, LogOut, Plus, Trash2, ArrowLeft |
| 13 | Selection and primary action | fail | agent-tool: the sub-view opened under the General section, so its back arrow sat mid-panel and the panel did not read as one view (§5.2 says the sub-view replaces the panel's content) |
| 14 | Empty space | fail | Same as 13: the node's Name and Description stayed above a tool's fields, pushing the tool's code below the fold |
| 15 | RTL fixtures | pass | agent-rtl: the Arabic node name aligns to the end in the header and the Name field; instructions wrap right to left; tool and variable names stay left to right as code |
| 16 | Names and errors | pass | Name errors say what is wrong and give an example ("Use letters, digits and underscores…", "For example lookupOrder.") |
| 17 | States | fail | agent-tool was shot mid-save ("Saving…" in the top bar), so its baseline would not be stable; empty Tools and Variables have designed dashed empty states |
| 18 | Focus ring | pass | No focus state for this screen; fields use the shared focus border |
| 19 | Beside Linear or Figma | fail | A new tool that opens already showing an error (3) |

Fixes made:
- The default input schema of a new code tool is `{"type": "object", "properties": {}}`.
- The open tool or exit is held by the node view, which hides General while a sub-view is open; the sub-view's back row is now the first thing under the tabs.
- The agent-tool state waits for "Saved" before shooting.
- Found while shooting: the Exits section's selector built a new Map on every store read and crashed the page; it now selects the workflow and derives with `useMemo`.
