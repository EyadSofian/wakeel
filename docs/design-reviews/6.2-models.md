# Design review — 6.2 Settings → Models

Screens: settings-models (default, focus, empty, loading, error, rtl, edit = key dialog open) · light + dark · 1440, 1280. The other three settings tabs were re-shot because the shared Settings description changed.

Motion: no new moments; the key and remove dialogs are the existing `Dialog`.

## Pass 1

| # | Check | Result | Evidence |
|---|---|---|---|
| 1 | Accent use | pass | Accent only on the active "Models" tab, the active rail item and "Save defaults" (and "Save key" inside the dialog) |
| 2 | Gradients, glows, decoration | pass | None |
| 3 | Status colours | pass | "Not set" is the neutral badge; no colour without a status |
| 4 | Dark hierarchy | pass | edit-dark: dialog on raised surface over the dimmed page, table rows on surface |
| 5 | Weights, sizes, caps | pass | Section titles `text-title`, rows `text-body`, key endings mono `text-code-small` |
| 6 | Sentence case | pass | "Provider keys", "Add key", "Replace", "Save defaults", "Utility model" |
| 7 | Truncation and overlap | pass | The long server address stays on one line beside the key ending, inside its column |
| 8 | Radii | pass | Table 14, inputs 8, dialog 18 |
| 9 | Shadows | pass | Only on the dialog, which floats |
| 10 | Spacing | pass | Sections 40 apart, fields 24, as on General |
| 11 | Identical card grids | pass | A table of the four providers |
| 12 | One icon set | pass | No new icons |
| 13 | Selection and primary action | pass | One primary button per section |
| 14 | Empty space | pass | Pickers held to the inspector's width, as on General |
| 15 | RTL fixtures | pass | rtl: the Arabic workspace name in the switcher; model ids and keys stay left to right as code |
| 16 | Names and errors | fail | default: the Settings description still read "name, members and API keys", leaving Models out |
| 17 | States | fail | default: "Remove" deleted a key at once, with no confirmation, though it cannot be undone (Revoke on API keys asks first) |
| 18 | Focus ring | pass | focus: ring on the first focusable control |
| 19 | Beside Linear or Figma | fail | The unconfirmed destructive "Remove" (17) |

Fixes made:

- 16: the description now ends "…the keys that call its API, and the models its bots use."
- 17: "Remove" opens a confirmation ("Bots that use this provider stop working until a key is added again. This cannot be undone.") with a danger button, like Revoke.
